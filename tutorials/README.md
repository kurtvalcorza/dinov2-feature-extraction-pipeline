## What changed from the inference-only tutorial

The previous notebook (`TASK-INFERENCE`, embedding obligations) embedded three synthetic images and reported a `not-measurable` verdict because a vector has no intrinsic metric. This notebook keeps the embedding contract as Section 5 (on real test photographs) and adds the adaptation contract around it: a real labelled photo corpus pinned per file, accuracy and macro-F1 in the carried `metrics.py` with a majority floor and a k-NN baseline as reference points, a linear probe (frozen policy) and a bounded unfreeze (unfrozen policy) selected on validation, before/after predictions, and an artifact that reloads. The per-batch `evaluation_report` still returns `not-measurable`; `pipe.evaluate` is the labelled corpus-level stage (`measured` / `measured-small-sample`).

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports) — the 180-row pinned photo table travels inside the carried `samples.py` — Section 3 carries the 3-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh clone lacks (the git-ignored `model.safetensors`), at the pinned revision; `verify_snapshot` re-hashes every entry; `DINOv2FeatureExtractionPipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files through `timm` with the snapshot's own `pretrained_cfg`; no cell outside the carried modules calls `huggingface_hub`, `timm`, `safetensors`, `urllib` or the model directly.
- **Data (DAT1–DAT9, ST6):** the default sample is 180 pinned objects — `<photo id>/medium.jpg` or `medium.jpeg`, each photo's own served extension recorded in the table from `inaturalist-open-data.s3.amazonaws.com`, 19,183,071 bytes in total, one SHA-256 each — every photograph CC0 by its own iNaturalist licence code, one per observer per species, each refused on any mismatch before it is decoded, and drawn by a seeded stratified shuffle into 108 / 24 / 48 records (`check_split_disjoint` asserts no shared photograph by decoded-pixel digest; `observer_overlap` reports the observers in more than one split). The template adds a second *External access* bullet naming the host, the byte count and the CC0 licence.
- **Stages (§4.1):** `fetch_corpus` + `read_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` + `class_names` + `check_split_disjoint` + `observer_overlap` + refusal probes (validation, with three digests) → `validate_inputs` + `pipe.embed` with sanity checks and two cosines (inference contract) → `majority_baseline` + `pipe.knn_baseline` + `pipe.adapt(trainable_blocks=0)` + `pipe.evaluate` (floor, baseline and frozen policy) → `pipe.adapt(trainable_blocks=TRAINABLE_BLOCKS)` (unfrozen policy, selected on validation) → `pipe.evaluate` on validation and test with the comparison (evaluation) → `pipe.classify` before and after + `evaluation_report` (inference) → `pipe.save_artifact` → `DINOv2FeatureExtractionPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** `embed` emits no score and a cosine is a similarity, not a score; the trained head's softmax is an argmax rule, not a calibrated confidence; accuracy and macro-F1 are computed over one labelled set with a fixed class order; no acceptance threshold ships.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the majority floor, the k-NN vote and the frozen policy are scored on the same 48 test photographs as the selected policy, per-class recall is printed beside every accuracy, the selection rule is stated (lowest validation log-loss, probe competing as epoch 0) and the notebook asserts only that the selected model beats the floor — a gain over the probe is the question, not an assertion; every metric is labelled as one seeded split of one small corpus with no dispersion estimate (one image ≈ 2.1 points).
- **Split integrity (SPL1–SPL8):** the split is seeded, stratified by species and image-disjoint by decoded-pixel digest; validation selects the epoch and policy and the test split is used for nothing but the final evaluation and the reload-parity check; the notebook counts observers in more than one split and states that real data must be split by photographer, session or device.
- **Ceilings (VAL6):** `MAX_IMAGE_SIDE` (4,096), `MAX_BATCH` (32), `EMBED_DIM` (384), the record bounds (8..20,000), the class bounds (2..100), the label pattern and the id pattern are stated in the Prerequisites and printed before the model runs; four dataset refusals and one image refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user images flow through the same validation, seeded stratified image-disjoint split, floors, both policies, evaluation, prediction, export and reload cells; images inside the uploaded zip are decoded from the archive, never extracted. The expected schema and the privacy guidance — photographs of people or private places are restricted data — are stated in the Prerequisites and in Section 4, and the training labels table is written to `outputs/dinov2_feature_extraction_train.csv` in that shape.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
